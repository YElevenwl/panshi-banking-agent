## ADR-001 · 概率推理层与确定性执行层分离

- **状态**：Proposed
- **背景**：LLM 可被注入、会幻觉，不能同时担任权限申请人、审批人和执行人。
- **决策**：LLM 只输出 `IntentProposal / DagProposal / ToolCallProposal / Explanation`；Orchestrator 校验；Policy Gate 裁决；Tool Gateway 验签 Permit 后执行。
- **备选**：
  - A. LLM 直接调用工具（否决：无法证明权限边界）。
  - B. LLM 输出风险等级并自我审批（否决：模型自评不可作为安全证据）。
  - C. 全部确定性规则、不用 LLM（否决：无法处理模糊表达，丢了赛题核心）。
- **证据**：E12（workflow vs agent）、E06（Policy Gate 位于 LLM 与业务系统之间）、E11（工具返回不可信）。
- **后果**：
  - 正面：权限可证明、可回归测试、可审计。
  - 负面：需要维护提案 schema 与节点白名单；灵活性下降。
- **验证**：越权/注入用例必须无法产生工具副作用；审计中 `permit.issued` 必须先于 `tool.executed`。

## ADR-002 · 资金主链路固定 DAG，只读场景允许受限动态计划

- **状态**：Proposed
- **背景**：赛题鼓励自主规划；但状态化业务中开放式 Agent 可靠性显著下降。
- **决策**：
  - 转账、冻结、下单、挂失等写操作：顶层 DAG 固定，LLM 只填充槽位与解释。
  - 账单/分析：LLM 可从节点库组合 ≤6 个节点，必须通过 schema、白名单、无环校验。
  - 禁止 LLM 生成任意代码或任意工具序列。
- **备选**：
  - A. 全动态 Agent（否决：pass^k 风险高，审计困难）。
  - B. 全固定脚本（否决：无法展示意图理解与追问能力）。
- **证据**：E12、E08（pass@1→pass^20 衰减）、E13（节点重放风险）。
- **后果**：
  - 正面：完成率与安全可控；答辩可讲“约束内自主”。
  - 负面：可能被评委认为不够“Agent”；用澄清、条件分支、跨场景联动补足。
- **验证**：固定 DAG 的 3 条场景 pass^20；动态计划只能出现在只读场景，且审计记录计划来源。

## ADR-003 · Policy Gate 独立于模型，输出签名 Execution Permit

- **状态**：Proposed
- **背景**：Prompt 不是执行边界；权限必须由模型之外的确定性系统裁决。
- **决策**：
  - Policy Gate 输入结构化事实，输出 `GREEN/YELLOW/RED/DENY + reason_codes + required_auth`。
  - 审批通过后签发 HMAC 签名 Permit，绑定 `subject/tool/params_hash/max_amount/auth/approvers/policy_version/expires/nonce`。
  - Tool Gateway 独立验签、验参、验 nonce、验主体；缺一不可。
- **备选**：
  - A. Prompt 里写“不要转账”（否决：可被注入绕过）。
  - B. LLM 输出 risk 字段（否决：不可证明）。
  - C. 只在 UI 层拦截（否决：API 可绕过）。
- **证据**：E02（操作授权/调用受控）、E06（Policy Gate/SoD/哈希链）、E14（幂等）。
- **后果**：
  - 正面：即使 Orchestrator 被攻破，也无法直接执行未授权动作。
  - 负面：Permit 生命周期与密钥管理增加复杂度。
- **验证**：Permit 重放、参数篡改、无 Permit 直连、跨主体调用 4 类用例全部拒绝。

## ADR-004 · 日累计额度原子预占，防拆单与并发

- **状态**：Proposed
- **背景**：赛题按“日累计”分级；两笔 800 元并发可能绕过 1000 元阈值。
- **决策**：
  - 判定使用“已提交 + 已冻结 + 在途”的投影额度。
  - `BEGIN IMMEDIATE` 事务 + `holds` 表原子预占；冲突则重算。
  - 单笔/累计/速度三规则叠加；超限升级 RED 或 DENY。
- **备选**：
  - A. 只看单笔金额（否决：可拆单）。
  - B. 事后对账（否决：已造成资金损失）。
- **证据**：E07（金额+可逆性分级）、E06（重要性阈值）、E14（幂等）。
- **后果**：
  - 正面：额度判定可证明；并发安全。
  - 负面：SQLite 写锁在高压下成为瓶颈；Demo 可接受，生产需数据库事务。
- **验证**：5×1000 拆单、2×800 并发、创建定时任务后改额 3 类用例。

## ADR-005 · 对外三级分类，内部增加可逆性/双人标签，只加强不降级

- **状态**：Proposed
- **背景**：赛题三级较粗；腾讯云实践按可逆性与金额分 auto/single/dual。
- **决策**：
  - 对外严格按赛题：GREEN/YELLOW/RED。
  - 内部增加 `reversible / irreversible / dual_required`，用于补偿策略与四眼复核。
  - 赛题列为 RED 的动作（改密、挂失/解挂、理财申购）不得降级。
- **备选**：
  - A. 完全采用 auto/single/dual（否决：与赛题口径冲突）。
  - B. 完全忽略可逆性（否决：补偿策略缺失）。
- **证据**：E07、E01、E02、附件赛题权限表。
- **后果**：
  - 正面：既符合赛题，又有工程纵深。
  - 负面：两套标签需要映射表与测试。
- **验证**：策略真值表覆盖 20 种组合；挂失/解挂必须 RED。

## ADR-006 · 双沙箱 + 七 Hook 安全中枢

- **状态**：Proposed
- **背景**：单点输入过滤不足；工具调用需要全链路管控。
- **决策**：
  - 七 Hook：输入、规划、授权前、工具前、工具后、输出前、收尾。
  - 工具沙箱：无网络、只读 FS、超时/内存上限、非 root。
  - 分析沙箱：子进程 + Node 权限模型；仅用于可选公式。
  - 核心资金链路不执行 LLM 生成代码。
- **备选**：
  - A. 只在入口做 prompt 过滤（否决：OWASP 明确过滤不能证明安全）。
  - B. 让所有代码在 Node `vm` 跑（否决：`vm` 不是安全边界）。
- **证据**：E04（百信双沙箱/Hook）、E11（OWASP）、E17（WorkBuddy）。
- **后果**：
  - 正面：控制点清晰、可测试、可审计。
  - 负面：Demo 的沙箱隔离强度不及生产；需在安全自评中声明。
- **验证**：外连/读密钥/超时/超大输出 4 类沙箱用例；Hook 顺序测试。

## ADR-007 · 工具结果默认不可信，taint 追踪到提案

- **状态**：Proposed
- **背景**：间接注入常通过交易备注、商户名、检索文档进入上下文。
- **决策**：
  - 工具结果 `TOOL_VERIFIED`（结构可信）但内容 `UNTRUSTED`。
  - 任何写操作提案若引用不可信事实 → `TAINTED_WRITE` → DENY 或要求用户重新确认。
  - 工具结果只作为数据字段，不进入指令区。
- **备选**：
  - A. 相信已授权工具的返回（否决：OWASP 明确所有工具返回不可信）。
  - B. 只做关键词过滤（否决：编码/多语言注入可绕过）。
- **证据**：E11、E01（输入安全）、E02（注入防御）。
- **后果**：
  - 正面：间接注入无法提权。
  - 负面：可能误伤正常含指令词的备注；用“写操作才阻断、只读告警”降低误伤。
- **验证**：备注注入、商户名注入、检索文档注入 3 类用例。

## ADR-008 · FactStore + 数字白名单 + 模板化回执

- **状态**：Proposed
- **背景**：LLM 可能编造余额、交易结果、日期。
- **决策**：
  - 所有事实入 FactStore，带来源、信任、时间、版本。
  - 回复生成后提取数字/金额/日期，逐一匹配 FactStore；不匹配即阻断。
  - 回执用确定性模板；LLM 只做可选润色，润色后仍需校验。
- **备选**：
  - A. 让 LLM 自检“是否幻觉”（否决：自评不可靠）。
  - B. 只靠 RAG（否决：检索也可能缺失/过期）。
- **证据**：E15（证据压缩/复核）、E08（按最终状态评分）、E11。
- **后果**：
  - 正面：零无依据数字可证明；审计可点开 fact_id。
  - 负面：模板化回复可能不够自然；用 LLM 润色 + 校验平衡。
- **验证**：空数据问余额、诱导确认虚假金额、旧对话数字复用 3 类用例。

## ADR-009 · 审批信封 + TOTP 交易挑战 + 双人复核

- **状态**：Proposed
- **背景**：弹窗确认不是人工接管；RED 需要强验证；可逆性不同。
- **决策**：
  - 信封包含意图、证据、工具与参数、影响范围、可逆性、补偿方案、过期、nonce。
  - RED 用 TOTP + 金额/收款人哈希绑定；Demo 标注“TOTP 模拟生物识别”。
  - 不可逆/超阈值动作可要求两个不同 approver。
- **备选**：
  - A. 只弹“确认/取消”（否决：盲签）。
  - B. 真实人脸识别（Demo 不可复现；生产集成点留出）。
- **证据**：E05（Revolut 生物识别）、E06（HITL 信封）、E03（人工监督）、E07（四眼）。
- **后果**：
  - 正面：审批可审计、防篡改、防钓鱼。
  - 负面：TOTP 仍是模拟；需在文档与答辩中明确。
- **验证**：审批超时、拒绝、参数篡改、重放 4 类用例。

## ADR-010 · 审计 append-only + 哈希链 + Merkle anchor + 回放

- **状态**：Proposed
- **背景**：金融场景要求决策链可追溯、可外部审计。
- **决策**：
  - JSONL 追加 + SQLite 索引 + UPDATE/DELETE trigger 阻断。
  - 每条事件哈希链接前一条；每 100 条写入 Merkle root 锚点。
  - `verify` 重算；`replay` 按 trace 展示；`simulate` 用记录 facts 重跑策略。
- **备选**：
  - A. 普通应用日志（否决：可改、字段不全）。
  - B. 只存数据库表（否决：可被管理员修改；缺 append-only 证据）。
- **证据**：E06（哈希链/外部审计回放）、E02（决策可溯）、E10（轨迹即 ground truth）。
- **后果**：
  - 正面：审计可证明；评测复用同一数据。
  - 负面：写入量增加；PII 脱敏与摘要存储需设计。
- **验证**：篡改一条事件 → verify 失败；正常链 → 通过；replay 字段完整。

## ADR-011 · 熔断状态机 + kill switch + 只读降级

- **状态**：Proposed
- **背景**：连续失败、注入、越权探测需要自动锁定；但不能死锁。
- **决策**：
  - CLOSED/OPEN/HALF_OPEN；阈值可配置；OPEN 时写拒绝、读允许。
  - 冷却 + 强验证 + 管理员解锁；每态有到期时间。
  - 全局 kill switch 停止 Permit 与调度，保留状态。
- **备选**：
  - A. 永久锁定（否决：不可恢复）。
  - B. 只告警不锁定（否决：高风险）。
- **证据**：E03（紧急停用/人工替代）、E06（HITL）、E17。
- **后果**：
  - 正面：攻击/故障被遏制，服务不完全中断。
  - 负面：阈值需调参；误熔断影响体验。
- **验证**：5 次失败→OPEN；读可用；强验证→HALF_OPEN；成功→CLOSED；kill switch 全链路。

## ADR-012 · 自研最小 DAG 内核（借鉴 LangGraph 语义）

- **状态**：Proposed
- **背景**：LangGraph 提供 checkpoint/interrupt，但节点恢复可能从头重放；副作用需额外保证。
- **决策**：
  - 自研 `dag/engine.js`：拓扑执行、节点边界 checkpoint、补偿栈、resume/cancel。
  - 副作用只在 Tool Gateway 发生，用稳定幂等键；节点可安全重放。
  - 保留与 LangGraph 概念映射（thread_id→run_id、interrupt→awaiting_user）。
- **备选**：
  - A. 直接用 LangGraph（否决：本机无 Python；框架重放语义增加副作用风险）。
  - B. 纯脚本无 DAG（否决：无法展示规划/中断/回退）。
- **证据**：E13（checkpoint/interrupt/重放）、E14（幂等）、E12。
- **后果**：
  - 正面：完全可控、可测试、零依赖。
  - 负面：需自行实现调度与恢复；工作量增加。
- **验证**：中断恢复两次不重复副作用；补偿栈逆序；checkpoint 完整。

## ADR-013 · Node 24 零依赖实现（待用户确认）

- **状态**：Proposed / 待确认
- **背景**：本机无 Python、git、docker；Node 24.22 可用，`node:sqlite` 验证通过。
- **决策**：
  - 主实现 Node 24 + 原生 HTTP/SSE + `node:sqlite` + 原生 Web UI。
  - 不引入运行时 npm 依赖；测试用 `node:test`。
  - Docker 配置提供但标注未本机验证。
- **备选**：
  - A. Python/FastAPI（需先安装 Python，且本机无法验证）。
  - B. Node + 框架（增加依赖与供应链风险）。
- **证据**：C6 环境校验；E17（默认可复现）；用户“或等效 DAG 引擎”授权。
- **后果**：
  - 正面：一条命令可跑；离线可复现；无供应链依赖。
  - 负面：评委可能偏好 Python；需在 README/答辩解释。
- **验证**：全新目录 `node src/server.js` 启动；`node --test` 全过；无 `npm install`。

## ADR-014 · 双 LLM 模式：MockLLM 默认 + OpenAI-compatible 可选

- **状态**：Proposed / 待确认
- **背景**：竞赛演示需要真实 AI；评测需要确定性、离线、可重复。
- **决策**：
  - 默认 `MockLLM`：规则+模板，确定性输出，保证测试与 20/20。
  - 可选 `OpenAILLM`：通过环境变量配置 base_url/key/model；演示视频使用。
  - 两种模式共用同一提案 schema、Policy Gate、DAG、审计。
- **备选**：
  - A. 只用真实 LLM（否决：网络/密钥/非确定性导致评测不可复现）。
  - B. 只用手写规则（否决：无法展示意图理解与口语化）。
- **证据**：E08（可靠性评测）、E12（ACI）、用户“AI 技术”要求。
- **后果**：
  - 正面：可复现 + 可展示。
  - 负面：Mock 可能被视为“假 AI”；答辩需现场切换真实模型并展示同一链路。
- **验证**：同一组用例在 Mock 与真实模型下都通过安全断言；真实模型延迟与失败有降级。
